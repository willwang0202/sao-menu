# Startup, HP display and refresh-rate design

The user supplied the menu/HP references, rainbow tunnel and login illustration, the anime reference https://www.youtube.com/watch?v=cCfJvBgAd3E, and Integral Factor reference https://www.youtube.com/watch?v=1hXfFHmWm7g. These specify the design. The existing online-account authorization remains applicable; no account service has been deployed.

The launcher and floating windows disable native macOS shadows; original sprites stay unmodified. Their low-alpha gray edges are retained. An independent, transparent, noninteractive HP window stays 24 points inside the primary monitor's work area across Spaces, including while the launcher hides. It uses the original 358×62 main sprite, 258×24 mask/bar at (78,12), and 218×42 extra sprite at y=47. Main CPU headroom and extra RAM headroom follow the supplied widget preset. The existing player name replaces the default Kirito label. Level is unavailable on macOS, displayed as LV:-- as in source fallback, and hpMax=250. Numbers animate linearly for 500ms; bar movement follows OutQuart for 500ms.

A cold foreground launch plays the bundled LinkStart.SAO.Kirito.wav, then Startup.SAO.NerveGear.wav. A time-based GPU tunnel precedes rotating sensor rings and the centered blue account/password panel. Reference media is viewed, not downloaded. These scenes are reconstructed vector/GPU artwork, not original game assets; exact original animation parity requires visual acceptance. Existing account sessions continue after the sequence. The panel can authenticate through the configured real account service; an unconfigured installation can continue offline or set the service address. No fake credentials or account success are displayed. Sound/Reduced Motion preferences apply. Completing startup is remembered for the process, so opening the menu and renderer reloads do not replay it. Login launch stays hidden and skips the introduction.

CSS and canvas/GPU animation use the compositor or requestAnimationFrame, with elapsed time rather than fixed steps. Native pointer sampling follows display frequency and renderers coalesce updates per animation frame. Isolated browser capture follows its window's display frequency, bounded by Electron's supported 240fps maximum. Raw BGRA pixels replace PNG/base64 frame serialization, and GPU curvature replaces 2,000 drawImage strips. Browser input retains the same inverse mapping. Recorded frame timing establishes actual performance on this Mac; matching refresh targets does not guarantee all hardware can maintain them.

Source, independent acceptance tests, verification records and release checksums are tracked in Git. The next release is 0.1.2. Imported resources and generated releases stay excluded; only the current release app and ZIP are retained after verification.
